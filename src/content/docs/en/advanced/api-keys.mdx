API keys allow you to interact with Prosopo services programmatically — for example, managing access control rules, provisioning site keys, or querying traffic data from your backend without using the portal UI. Every endpoint an API key can reach is listed in the [API reference](/en/advanced/api/).

API key management is available to accounts with the API feature enabled. Check your account's feature flags in the portal.

## Creating an API Key

1. Log in to the [Prosopo Portal](https://portal.prosopo.io)
2. Navigate to **API Keys** from the main menu
3. Click **Create API Key**
4. Fill in the required fields:
   - **Name** (required): A descriptive label for the key, e.g. "Production Backend" or "CI/CD Pipeline"
   - **Expiration Time** (optional): Time in seconds until the key expires. Leave it empty and the key expires after 30 days — every key expires, so plan to rotate.
   - **Permissions** (required): Select which operations this key can perform (see below)
5. Click **Create API Key**

<Image src={ApiKeyCreate} alt="prosopo portal create API key dialog" style="margin: 20px auto;"/>

The full key is shown once the key is created, and stays retrievable afterwards from the same page (and from `/api-keys/get`) — so anyone who can read your portal account can read the key. Delete a key you no longer use rather than leaving it in the list.

## Permissions

Each API key is scoped to a specific set of permissions. Only grant the permissions the key actually needs.

### Access Rules

| Permission | Description |
|-----------|-------------|
| `getRules` | List access control rules |
| `getSuggestion` | Not yet in use — no endpoint checks it |
| `getSuggestions` | Not yet in use — no endpoint checks it |
| `applySuggestions` | Not yet in use — no endpoint checks it |
| `createRule` | Create a new access control rule |
| `deleteRule` | Delete an access control rule |
| `deleteRuleGroup` | Delete an access control rule group |

### Sites

| Permission | Description |
|-----------|-------------|
| `getSite` | Get a single site's details |
| `getSites` | List all sites |
| `createSite` | Create a new site |
| `deleteSite` | Delete a site |
| `updateSite` | Update site settings |

### API Keys

| Permission | Description |
|-----------|-------------|
| `getApiKeys` | List API keys |
| `createApiKey` | Create a new API key |
| `updateApiKey` | Not yet in use — keys cannot be edited, only created and deleted |
| `deleteApiKey` | Delete an API key |

### Users

| Permission | Description |
|-----------|-------------|
| `getUsers` | List team members |
| `createUser` | Invite a new team member |
| `updateUser` | Update a team member's role |
| `deleteUser` | Remove a team member |

### Traffic

| Permission | Description |
|-----------|-------------|
| `getTraffic` | Query traffic analytics data |

### Search Captcha Records

| Permission | Description |
|-----------|-------------|
| `searchCaptchaRecords` | Search and retrieve CAPTCHA audit records |

## Using an API Key

Include the API key in the `Authorization` header of your HTTP requests:

```bash
curl -X POST https://api.prosopo.io/access-control/get \
  -H "Authorization: Bearer YOUR_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{"limit": 20}'
```

Or in code:

```javascript
const response = await fetch('https://api.prosopo.io/access-control/get', {
  method: 'POST',
  headers: {
    'Authorization': `Bearer ${apiKey}`,
    'Content-Type': 'application/json',
  },
  body: JSON.stringify({ limit: 20 }),
});
```

The [API reference](/en/advanced/api/) lists every endpoint, the permission it requires and the body it expects.

## Managing API Keys

### Viewing Keys

The API Keys page shows all keys for your account:

- **Name**: The label you gave the key
- **Created**: When the key was created
- **Expires**: When the key expires (or "Never" for non-expiring keys)
- **Permissions**: Which operations the key can perform

### Deleting Keys

To revoke an API key, click the delete button next to it in the API Keys list. The key is immediately invalidated — any requests using it will be rejected.

Deletion is permanent and cannot be undone. If you delete a key by mistake, create a new one and update your application with the new key.

## Security Best Practices

### Principle of Least Privilege

Only grant the permissions each key actually needs. A key that only reads traffic figures for a dashboard should carry `getTraffic` alone — it does not need `createSite` or `deleteRule`.

### Use Expiring Keys for Temporary Access

When granting access to a contractor, CI/CD pipeline, or temporary integration, set an expiration time so the key is automatically invalidated.

### Rotate Keys Regularly

For long-lived production keys, rotate them periodically:

1. Create a new key with the same permissions
2. Update your application to use the new key
3. Verify the new key works
4. Delete the old key

### Never Expose Keys Client-Side

API keys should only be used in server-side code. Never embed them in frontend JavaScript, mobile apps, or public repositories. For client-side CAPTCHA integration, use site keys instead — see [Client-side Rendering](/en/basics/client-side-rendering/). Server-side verification uses your site's secret key rather than an API key — see [Server-side verification](/en/basics/server-side-verification/).

### Monitor Usage

Review the Audit page and traffic analytics to detect any unexpected API key usage patterns that could indicate a compromised key.
