The Procaptcha plugin introduces new WordPress filters and hooks, allowing you to customize its behavior.

## 1. Captcha visibility

By default, Procaptcha is displayed only to unauthorized users.

To control this behavior, besides the plugin settings, you can use the `is_captcha_present` hook.
For example, to make Procaptcha required for everyone, add the following code to your theme's functions.php file:

```php
add_filter('prosopo/procaptcha/is_captcha_present', '__return_true');`
```

## 2. Custom error message

You can customize the default error message by adding this code to your theme's functions.php file:

```php
add_filter('prosopo/procaptcha/validation_error_message', function (string $message): string {
    return __('Custom error message', 'my-theme');
});
```

## 3. Customizing Procaptcha attributes

Beyond the style preferences in the plugin settings, you can customize any supported [Procaptcha data attributes](https://docs.prosopo.io/en/basics/client-side-rendering/#procaptcha-options) using the **prosopo/procaptcha/captcha_attributes** filter.

```php
add_filter('prosopo/procaptcha/captcha_attributes', function (array $attributes): array {
    $attributes['language'] = 'de';
    return $attributes;
});
```

## 4. Visitor IP address

From version 1.23.0, the plugin sends the visitor's IP address with each verification request, which improves bot detection. By default it uses `REMOTE_ADDR`. If your site is behind a proxy or CDN such as Cloudflare, `REMOTE_ADDR` is the proxy's address, so pass the real visitor IP with the **prosopo/procaptcha/visitor_ip** filter:

```php
add_filter('prosopo/procaptcha/visitor_ip', function (string $ip): string {
    return $_SERVER['HTTP_CF_CONNECTING_IP'] ?? $ip;
});
```

Only trust a forwarded header that your proxy sets. Values that aren't a valid IP address aren't sent.

## 5. Verification result

From version 1.24.0, the **prosopo/procaptcha/verification_result** action runs after each verification request with the result and the API response, so you can record the score or the reason a submission was rejected. When `WP_DEBUG` is on, failed verifications are also written to the debug log.

```php
add_action('prosopo/procaptcha/verification_result', function (bool $verified, array $response): void {
    // $response: verified, status, score, reason, error, sessionId
    if (! $verified) {
        error_log('Procaptcha rejected a submission: ' . ($response['reason'] ?? 'unknown'));
    }
}, 10, 2);
```

## 6. JavaScript events

From version 1.24.0, the widget dispatches these events, which bubble up to the form and the document:

- `prosopo-procaptcha:filled`: the visitor solved the captcha. `event.detail.token` holds the token.
- `prosopo-procaptcha:cleared`: the token expired, the widget errored or it was reset.

A token can be verified only once. The plugin resets the captcha after AJAX submissions of the supported form plugins. For your own AJAX forms, dispatch `prosopo-procaptcha:reset` on the form (or any element that contains the captcha, or `document` to reset all of them):

```js
document.addEventListener('prosopo-procaptcha:filled', (event) => {
    console.log('Token received', event.detail.token);
});

document.addEventListener('prosopo-procaptcha:cleared', (event) => {
    console.log('Token expired or the widget was reset', event.target);
});

// Reset the captcha in a form, e.g. after your own AJAX submission.
form.dispatchEvent(new Event('prosopo-procaptcha:reset'));
```

## 7. Forms with Procaptcha in tests

If your tests involve forms with Procaptcha, you can bypass the Procaptcha by adding the following constant to your wp-config.php file:

```php
define('PROSOPO_PROCAPTCHA_ALLOW_BYPASS', true);
```

In your tests, add an **input[name=procaptcha-response]** element with the value **bypass** to any form to simulate Procaptcha completion.

**Important:** This bypass constant should only be used in development environments.
