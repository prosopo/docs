O plugin Procaptcha introduz novos filters e hooks do WordPress, permitindo que você personalize seu comportamento.

## 1. Visibilidade do Captcha

Por padrão, o Procaptcha é exibido apenas para usuários não autorizados.

Para controlar esse comportamento, além das configurações do plugin, você pode usar o hook `is_captcha_present`.
Por exemplo, para tornar o Procaptcha obrigatório para todos, adicione o seguinte código ao arquivo functions.php do seu tema:

```php
add_filter('prosopo/procaptcha/is_captcha_present', '__return_true');`
```

## 2. Mensagem de Erro Personalizada

Você pode personalizar a mensagem de erro padrão adicionando este código ao arquivo functions.php do seu tema:

```php
add_filter('prosopo/procaptcha/validation_error_message', function (string $message): string {
    return __('Mensagem de erro personalizada', 'my-theme');
});
```

## 3. Personalizando Atributos do Procaptcha

Além das preferências de estilo nas configurações do plugin, você pode personalizar qualquer [atributo de dados do Procaptcha](https://docs.prosopo.io/pt-br/basics/client-side-rendering/#procaptcha-options) suportado usando o filter **prosopo/procaptcha/captcha_attributes**.

```php
add_filter('prosopo/procaptcha/captcha_attributes', function (array $attributes): array {
    $attributes['language'] = 'de';
    return $attributes;
});
```

## 4. Correspondência do IP do visitante

Com a correspondência de IP ativada, o plugin envia o endereço IP do visitante em cada solicitação de verificação, e o Procaptcha rejeita um token resolvido a partir de outro IP. Ela fica **desativada por padrão**: a maioria dos sites está atrás do Cloudflare ou de outro proxy, e enviar o endereço do proxy em vez do visitante rejeitaria visitantes reais.

Para ativá-la, vá em **Configurações > Prosopo Procaptcha > General** e escolha de onde vem o IP do visitante em **Correspondência do IP do visitante**:

- **Ativado – o site está atrás do Cloudflare**: o cabeçalho `CF-Connecting-IP`.
- **Ativado – o site está atrás de outro proxy**: o primeiro endereço do cabeçalho `X-Forwarded-For`.
- **Ativado – os visitantes se conectam diretamente**: `REMOTE_ADDR`.

Escolha apenas um cabeçalho definido pelo seu proxy, pois os visitantes podem enviar esses cabeçalhos por conta própria. Se o cabeçalho estiver ausente ou não for um endereço IP válido, nada é enviado e o token é verificado sem correspondência de IP.

Para outras configurações, o filtro **prosopo/procaptcha/visitor_ip** recebe o IP da configuração (vazio quando desativada) e `REMOTE_ADDR`. Retorne o IP a enviar, ou uma string vazia para não enviar nenhum:

```php
add_filter('prosopo/procaptcha/visitor_ip', function (string $ip, string $remote_addr): string {
    return $_SERVER['HTTP_TRUE_CLIENT_IP'] ?? $ip;
}, 10, 2);
```

A versão 1.23.0 enviava `REMOTE_ADDR` por padrão. Atualize para a 1.24.0 ou posterior se o seu site estiver atrás de um proxy.

## 5. Resultado da verificação

A partir da versão 1.24.0, a action **prosopo/procaptcha/verification_result** é executada após cada solicitação de verificação com o resultado e a resposta da API, para que você possa registrar a pontuação ou o motivo pelo qual um envio foi rejeitado. Quando `WP_DEBUG` está ativo, as verificações que falharam também são gravadas no log de depuração.

```php
add_action('prosopo/procaptcha/verification_result', function (bool $verified, array $response): void {
    // $response: verified, status, score, reason, error, sessionId
    if (! $verified) {
        error_log('Procaptcha rejected a submission: ' . ($response['reason'] ?? 'unknown'));
    }
}, 10, 2);
```

## 6. Eventos JavaScript

A partir da versão 1.24.0, o widget dispara estes eventos, que se propagam até o formulário e o documento:

- `prosopo-procaptcha:filled`: o visitante resolveu o captcha. `event.detail.token` contém o token.
- `prosopo-procaptcha:cleared`: o token expirou, o widget apresentou um erro ou foi redefinido.

Um token só pode ser verificado uma vez. O plugin redefine o captcha após os envios AJAX dos plugins de formulário compatíveis. Nos seus próprios formulários AJAX, dispare `prosopo-procaptcha:reset` no formulário (ou em qualquer elemento que contenha o captcha, ou em `document` para redefinir todos):

```js
document.addEventListener('prosopo-procaptcha:filled', (event) => {
    console.log('Token received', event.detail.token);
});

document.addEventListener('prosopo-procaptcha:cleared', (event) => {
    console.log('Token expired or the widget was reset', event.target);
});

// Reset the captcha in a form, e.g. after your own AJAX submission.
form.dispatchEvent(new Event('prosopo-procaptcha:reset'));
```

## 7. Formulários com Procaptcha em Testes

Se seus testes envolvem formulários com Procaptcha, você pode ignorar o Procaptcha adicionando a seguinte constante ao seu arquivo wp-config.php:

```php
define('PROSOPO_PROCAPTCHA_ALLOW_BYPASS', true);
```

Em seus testes, adicione um elemento **input[name=procaptcha-response]** com o valor **bypass** a qualquer formulário para simular a conclusão do Procaptcha.

**Importante:** Esta constante de desvio deve ser usada apenas em ambientes de desenvolvimento.
